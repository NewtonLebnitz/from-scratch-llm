# Training and Data Workflow

## Pretraining

- Data: processed English and Chinese FineWiki documents, sampled with equal language weights of 50% each.
- BPE: learn the byte-level vocabulary and ordered merges using TRAIN documents only; vocabulary size 32k.
- Train each architecture independently from scratch for 45,000 parameter updates. Sequence length 512, microbatch 12, accumulation 4, effective batch 48: 24,576 tokens per update.
- Each architecture processes 1,105,920,000 training tokens. This includes repeated sampling and is not a count of unique source tokens.
- Objective: next-token cross-entropy at all valid positions. DEV uses an independent random state and does not advance the training sampler.
- Checkpoints save model, optimizer, sampler and random states. Tests compare resumed training with uninterrupted training.

## Supervised Fine-Tuning

The historical task contains 14,336 bilingual QA records covering 64 domain facts and 16 everyday tasks, with multiple question formulations. DEV selects checkpoints; evaluation questions are not reused for tuning. The 256 domain questions and 32 everyday questions are different formulations within a limited knowledge scope, not 288 independent facts.

SFT computes next-token cross-entropy only on answer tokens and the terminator, masking prompt and evidence tokens. Answers must actually be generated by the model. All three standard routes restart from the same standard pretrained checkpoint. Hopfield full-parameter SFT starts from its own pretrained checkpoint, not from an older SFT model.

## Execution and Scale

- `configs/*demo.json` are two-step CPU execution examples. `configs/pretrain-*-18l.json` specify the full architecture and pretraining budget.
- Full-size SFT requires a budget appropriate for your data, answer lengths and hardware. The two-step example does not reproduce the full historical 14,336-record training run.
- See the [usage guide](USAGE.md) for commands, data formats, three standard SFT routes and Hopfield operations.
- GPU commands require explicit `--device cuda`. Select a single GPU you are authorized to use before starting; CPU is the default. This release does not include multi-GPU code from personal research.
